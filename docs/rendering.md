# Deterministic visual previews

Run `motion-engine render SPEC --output-dir DIR`. For a spec requiring `video/mp4`, this writes numbered PNG frames, `preview.mp4`, and `render-manifest.json`. The output path must not exist. Rendering uses a temporary sibling directory and publishes the output only after success; a failed render leaves no partial result. `--frames-only` omits MP4 for diagnostics; `--mp4` forces MP4 when it is not a required deliverable. `--scale 0.5` gives a faster smaller preview. `--font-dir PATH` adds a directory of licensed project fonts. `--max-frames` raises the explicit frame safety limit.

Add `--resume` to reuse an existing output after [run integrity checks](runs.md). Frame and MP4 hashes, the source revision, and the render options must all match.

Supported M2 primitives: editable-source `text`, `shape` rectangles, `chart.bar`, and `chart.line`; local raster `image` layers; hashed moving `video.frames` plates; `opacity` and frame-based `x`/`y` position keyframes for text, rectangles, images, and video plates; bounded `scale` keyframes for images and video plates; `reveal` keyframes for charts; and text disclosures. Position values are canvas coordinates and may begin up to one canvas width or height offscreen for entrances. Scene cuts and exact-frame fades through the project background are supported. Set an incoming scene's `transitionIn` to `fade` and `transitionFrames` from 2 to 120; the window must fit both adjacent scenes. The first half fades the outgoing scene and the second half reveals the incoming scene. This is a nonoverlapping visual transition and does not fade audio. Charts bind to MotionSpec datasets and map exact numeric values to geometry. The renderer never reads values from a generated image. Frames are numbered from `000000.png` to the final frame, and MP4 is encoded with FFmpeg at the rational MotionSpec frame rate.

A `counter` keeps its numeric start and end values separate from its prefix, suffix, decimal precision, font, and color. A frame-based `value` animation controls the displayed number using the same supported easing names as other tracks. Values must be finite; decimals are limited to six. Counter bounds participate in text safe-area QA. The initial formatter uses fixed decimal notation and explicit optional digit localization, so an agent must supply the intended currency symbol, unit, scale, and precision from verified source data.

An `audio` element can bind to an available, hashed WAV asset and declare its exact `startFrame` and `endFrameExclusive`. The initial mixer accepts mono 16-bit PCM at 48 kHz and an optional `params.gainDb` from -60 to +12. It aligns frame boundaries to the nearest sample, mixes overlapping clips without automatic limiting, rejects clipping and clips shorter than their declared window, writes `mix.wav`, and muxes AAC into MP4. `--frames-only` still writes the WAV mix for review. Speech-to-text alignment, stereo, resampling, compressed inputs, fades, ducking, loudness normalization, and delivery audio QA remain future work. A beat's `voice` text alone is not an audio asset.

`examples/audio-card.motion.json` is a public synthetic fixture with a one-second tone from frame 15 to frame 45. It contains no private voice recording.

Image assets support PNG, JPEG, and WebP, with `contain`, `cover`, or `stretch` fit. The URI is relative to the MotionSpec file when run through the CLI. The asset must be `available`, carry a SHA-256 hash, and remain inside that directory tree. A changed or missing image stops rendering before output is written. See `examples/image-card.motion.json` for a fully public synthetic example.

Moving plates use a `video` element bound to an available, hashed `video.frames` ZIP asset. The ZIP contains `manifest.json` with `formatVersion: 1`, width, height, rational frame rate, and frame count, plus exactly `frames/000000.png` through the last declared frame. The plate frame rate must match the project exactly. `params.sourceStartFrame` selects a source-frame offset, and the remaining frames must cover the element duration. `fit` supports contain, cover, and stretch. No plate audio is imported; audio remains a separate timed element. The renderer decodes only the needed frame and preserves transparent PNG pixels. The two public moving examples are `examples/moving-landscape.motion.json` and `examples/moving-portrait.motion.json`.

Use `motion-engine import-video SOURCE.mp4 --output plate.zip --fps-num 24 --fps-den 1 --frames 48 --start-ms 0` to normalize a supplied or generated video into an exact-frame plate. The command accepts MP4, MOV, WebM, and MKV, verifies the decoded frame count and dimensions, and reports the source hash, output hash, and conversion settings. Add the resulting asset to the MotionSpec and retain its source and conversion record. This is a raster proxy for preview and compositing; it does not make the contents of a generated shot editable in Adobe. The current importer uses FFmpeg's `fps` filter, which can duplicate or discard source frames to reach the requested rate, so visual inspection remains required. Long, high-resolution footage needs a more efficient proxy path.

Text accepts explicit newlines. Set `params.wrap: true` to wrap at spaces within the element bounds; wrapping is off by default so authored line breaks stay exact. The renderer checks each line and the full text block against its bounds and fails on overflow or an unbreakable word. It preserves the MotionSpec text and uses libraqm for requested right-to-left shaping. Word breaking for scripts without spaces, rich text, and locale-aware number formatting remain future work.

This is a **raster preview**, not an Adobe project or a final production master. Native moving-footage integration, vector images, more primitives, overlapping transitions, rich typographic layout, and broader native project generation still need adapters. Unsupported content raises an error before rendering frames. A missing requested font is recorded as a substitution warning in the manifest; production must install and visually approve the intended font. Right-to-left preview requires Pillow built with libraqm. The preview renderer does not replace a language reviewer.
On a system where Pillow lacks libraqm, left-to-right previews still render; explicit right-to-left text raises a clear error. The Windows CI wheel currently tests this error path, while the Linux CI wheel tests the rendered right-to-left example.
